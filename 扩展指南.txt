TKOT 扩展指南 —— 新增一种 TNT 道具
==================================================

以新增一种叫 <name> 的变体为例（例如 shock / cluster / heavy）。
只要 4 个文件 + 1 行发放，其余机制全部自动复用。


一、必须遵守的 4 条约定
--------------------------------------------------
1. 物品的 custom_data 里必须有 tnt:true 和 type:"<name>"
   → items/clear_tnt、states/overall/clean 靠 tnt:true 统一清理
   → 进度靠 type 区分变体，不能省略

2. 物品组件里必须保留 consumable
   → 玩家"吃"棍子时才触发 consume_item 进度
   → 消耗就是 consumable 自动扣 1，不要再写 clear

3. summon 出来的 TNT 必须带 thrown_tnt 标签
   → states/reset 的 kill @e[tag=thrown_tnt] 靠它清理残留
   → owner 写入也靠它定位

4. 瞄准计算一律走 item:common/aim
   → 不要复制那 36 行，改速度只改它一处


二、新建的文件（4 个）
--------------------------------------------------

【1】进度：data/item/advancement/<name>_tnt_stick.json
--------------------------------------------------
{
  "criteria": {
    "consume": {
      "trigger": "minecraft:consume_item",
      "conditions": {
        "item": {
          "items": "minecraft:stick",
          "predicates": {
            "minecraft:custom_data": "{tnt:true,type:\"<name>\"}"
          }
        }
      }
    }
  },
  "rewards": {
    "function": "item:<name>_tnt/throw_tnt"
  }
}

注意：predicates 里的字符串必须和物品 custom_data 完全对应。


【2】投掷入口：data/item/function/<name>_tnt/throw_tnt.mcfunction
--------------------------------------------------
# 撤销进度，否则 consume_item 只会触发一次
advancement revoke @s only item:<name>_tnt_stick

# 公共瞄准：探针 → 方向 → storage tkot:throw → 删探针
function item:common/aim

# 召唤
execute at @s run function item:<name>_tnt/throw_tnt_with_macro with storage tkot:throw


【3】召唤宏：data/item/function/<name>_tnt/throw_tnt_with_macro.mcfunction
--------------------------------------------------
$summon minecraft:tnt ~ ~1.62 ~ {Tags:["thrown_tnt"],fuse:60,Motion:[$(mx)d,$(my)d,$(mz)d]}
data modify entity @e[type=minecraft:tnt,tag=thrown_tnt,limit=1,sort=nearest] owner set from entity @s UUID

fuse 单位是 tick：20 = 1 秒，60 = 3 秒（默认保险引信）。
如果这个变体还需要"每 tick 做点什么"（例如落地即炸），就在 Tags 里再加一个自己的标签，
见下面第四节。


【4】发放：改现有文件即可，不用新建
--------------------------------------------------
· 持续补给（每 3 秒）  → data/tkot/function/states/2/give_item.mcfunction 里加一条 give
· 每局只发 1 个        → data/tkot/function/states/2/spread.mcfunction 里加一条 give（瞬爆弹就是这么发的）
· 调试手动发           → data/item/function/temp.mcfunction 里加一条 give @s

give 模板（整行复制，改三处：type、显示名、数量）：

give @a[team=!debug,gamemode=!spectator,scores={statu=2}] minecraft:stick[minecraft:max_stack_size=99,minecraft:use_cooldown={seconds:0.5,cooldown_group:"tnt_throw"},minecraft:custom_data={tnt:true,type:"<name>"},minecraft:consumable={consume_seconds:0,animation:"none",sound:"intentionally_empty",has_consume_particles:false},minecraft:item_model="minecraft:tnt",minecraft:item_name={"text":"<显示名>"}] 1


三、不用改的东西（已自动覆盖）
--------------------------------------------------
· items/clear_tnt       —— 用 custom_data~{tnt:true}，新变体自动被清
· states/overall/clean  —— 每秒清所有无 tkot_keep 的地面物品
· states/reset          —— kill @e[tag=thrown_tnt]，只要第 3 条约定满足
· lobby 相关的一切      —— 与弹药无关


四、需要"每 tick 行为"的变体（可选）
--------------------------------------------------
以瞬爆弹为例，它需要"贴地就引爆"：

1) 召唤时多打一个标签
   $summon minecraft:tnt ~ ~1.62 ~ {Tags:["thrown_tnt","instant_explode_tnt"],fuse:60,...}

2) 新建 data/item/function/<name>_tnt/tick.mcfunction
   execute as @e[type=minecraft:tnt,tag=<你自己的标签>] at @s unless block ~ ~-0.1 ~ #minecraft:air run data modify entity @s fuse set value 1

3) 在 data/item/function/tick/tick1.mcfunction 里加一行
   function item:<name>_tnt/tick

tick1 是全局每 tick 循环，已经在跑了（item:load 里调度），直接加调用即可。


五、想做"不同变体不同初速度"（进阶）
--------------------------------------------------
目前 item:common/aim 把速度系数写死成 0.000015（= 1.5 格/刻），它已经是宏函数（带 $(lat)）。
若要每个变体不同速度，再加一个 $(spd) 参数：

  $execute store result storage tkot:throw mx double $(spd) run scoreboard players get @e[tag=tmp_dir,limit=1] calc_x
  （my / mz 同理）

然后在 throw_tnt 里先写 storage：

  data modify storage tkot:throw spd set value 0.000015    # 或别的系数
  function item:common/aim with storage tkot:throw

注意：一旦加了 $(spd)，所有调用方（normal / instant / multishot）都必须保证
tkot:throw.spd 已存在，否则会报宏参数缺失。


六、改完必做
--------------------------------------------------
1. /reload
2. 退出并重新进入存档（进度文件改动必须重新扫描，否则新的 criteria 不生效）
3. 检查聊天栏有没有 <unknown function> / 宏参数缺失
4. 拿新道具试扔一次，再看 states/reset 后场上是否干净


七、常见坑
--------------------------------------------------
· 进度 criteria 里的 type 和物品 give 里的 type 不一致 → 扔不出来
· 忘了 advancement revoke → 只能扔第一次
· TNT 没打 thrown_tnt → 回合结束清不掉，会在结算/大厅爆炸
· 忘了 consumable → 棍子吃不掉，进度不触发
· 复制了 common/aim 的内容而不是调用 → 以后改速度要改多处
· 改完进度文件没退出重进存档 → 看起来"什么都没生效"


八、扇形多重射击 —— 完整实例
--------------------------------------------------
现成例子：item:multishot_tnt（一次 3 颗、呈扇形散开、fuse 与初速和普通弹一致）。

核心思路：不用三角函数，用「探针侧移」做出方向偏转。

  探针原本放在「眼睛前方 10 格」，连线方向 = 正前方。
  把探针改成「前方 10 格 + 侧向 lat 格」，连线就带上了横向分量：
      Motion = 0.15 × (10·前方 + lat·左方)
      → 前进 1.5 格/刻，同时横移 0.15×lat 格/刻
  lat = 1.5 时横移约 0.225 格/刻 ≈ 4.5 格/秒，三颗 1 秒后散开约 9 格。

为什么用 ^ 局部坐标：它跟着视线旋转，所以仰视/俯视都正确。
如果改用「水平垂直向量」那套算法，垂直看时水平分量趋近 0，扇形会失效。

【1】公共瞄准 item:common/aim —— 已经参数化
    $execute anchored eyes run summon minecraft:marker ^$(lat) ^ ^10 {Tags:["tmp_dir"]}
    其余计算不变，结果仍写进 tkot:throw 的 mx/my/mz。
    调用方必须先写 data modify storage tkot:throw lat set value <数值>，
    否则会报宏参数缺失（普通弹/瞬爆弹现在都显式写 lat = 0）。

【2】投掷入口 data/item/function/multishot_tnt/throw_tnt.mcfunction
    advancement revoke @s only item:multishot_tnt_stick

    data modify storage tkot:throw lat set value 1.5
    function item:common/aim with storage tkot:throw
    execute at @s run function item:multishot_tnt/throw_tnt_with_macro with storage tkot:throw

    data modify storage tkot:throw lat set value 0
    function item:common/aim with storage tkot:throw
    execute at @s run function item:multishot_tnt/throw_tnt_with_macro with storage tkot:throw

    data modify storage tkot:throw lat set value -1.5
    function item:common/aim with storage tkot:throw
    execute at @s run function item:multishot_tnt/throw_tnt_with_macro with storage tkot:throw

    data modify entity @e[type=minecraft:tnt,tag=multishot_tnt,sort=nearest,limit=3] owner set from entity @s UUID

【3】召唤宏 data/item/function/multishot_tnt/throw_tnt_with_macro.mcfunction
    只召唤 1 颗，由上面循环调用 3 次：
    $summon minecraft:tnt ~ ~1.62 ~ {Tags:["thrown_tnt","multishot_tnt"],fuse:60,Motion:[$(mx)d,$(my)d,$(mz)d]}

【4】调参
    · 散得更开：把三个 1.5 改成 2.5 / 3
    · 5 颗：补成 3 / 1.5 / 0 / -1.5 / -3 的对称组合
    · 竖直扇形：把 aim 里的 ^$(lat) 改成 ^ ^$(lat) ^10（lat 变成上下偏移）
    · 想要「平行排开」而不是扇形：那是另一种做法 —— 三颗方向相同、召唤位置错开，
      summon 里把 ~ ~1.62 ~ 换成 ^-0.6 ^ ^1 之类，但那样不散开

【5】清理不用改
    三颗都带 thrown_tnt，states/reset 的 kill @e[tag=thrown_tnt] 会一起清掉。
    额外打的 multishot_tnt 标签只是给 owner 定位用的，不参与清理。


九、新增一张地图
--------------------------------------------------
前提：新地图也是 48×48×48，落点和现有地图完全相同
（原点 (0,0,-48)，区域 x 0..47 / z -48..-1，中心 (24,-24)）。
这样场上所有坐标都不用改，只有模板名不同。

【1】保存结构模板
    · 用结构方块框住整张图，单边不能超过 48
    · 保存的名字随意（例如 map_2_1），导出成 .nbt
    · 放到 tkot/data/tkot/structure/<模板名>.nbt
    · 模板 id 就是 tkot:<模板名>，例如 tkot:map_2_1

【2】新建 tkot/data/tkot/function/maps/mapN.mcfunction
    直接复制 map1.mcfunction 改三处：

    data modify storage tkot:map id     set value <N>            ← 地图编号
    data modify storage tkot:map name   set value "<显示名>"      ← map_intro 会显示
    data modify storage tkot:map struct set value "tkot:<模板名>" ← 模板 id

    ★ 后面那一堆 x1/y1/z1/x2/z2/x/z/y_spawn/y_debug/max_height 全部照抄，不要动。

    ★ 时间与刷怪规则必须在这张图里显式写，例如：

      time set day
      gamerule spawn_monsters false

      原因：map1 会设成 night + 刷怪，这些都是【全局状态、不会自动复原】。
      不写的话，新地图会继承上一张图的昼夜和刷怪规则。

【3】改 tkot/data/tkot/function/maps/pick.mcfunction
    三件事：

    ① 总数
       data modify storage tkot:map total set value <地图总数>

    ② 抽图行
       地图只有 1 张时（random 范围必须 ≥2，所以不能写 1..1）：
         scoreboard players set #map_num int 1
       地图 ≥2 张时：
         execute store result score #map_num int run random value 1..<总数>

    ③ dispatch（每张图一行）
       execute if score #map_num int matches <N> run function tkot:maps/mapN

【4】不用改的东西（因为共用场地）
    · forceload add / remove 的坐标 —— 所有 48×48 图都是 0 -48 47 -1
    · maps/map1_spectate 的包围盒与观察点 —— 所有图共用一份
    · states/3/map_returen/* 的清理范围 —— 参数从 storage 读，自动跟随
    · states/3/place、place_quiet —— 模板名从 storage 读，自动跟随
    · states/2/spread —— 出生点从 storage 读，自动跟随

【5】测试
    · /reload（新加了 structure 文件，必须重新加载数据包才能被扫描到）
    · 想指定测某张图：把 pick 里改成 scoreboard players set #map_num int <N>
    · 检查聊天栏有没有「开战前铺图失败：tkot:xxx」—— 有的话就是模板名或文件路径不对
    · 开一局，看完 states/3 复位后场地上是否干净（说明 max_height 和清理范围对得上）

【6】如果新地图【不是】48×48，或落点不同
    那么共用场地的前提就不成立了，需要额外做：
    · maps/pick 的 forceload 改成按图号区分
    · 新增 maps/mapN_spectate（包围盒 = 新图尺寸）
    · states/overall/in_game 里的边界判定改成按图号 dispatch
    · states/3/finish 与 states/abort 的 forceload remove 改成按图号区分
    · mapN 里的 x1/y1/z1/x2/z2/x/z/max_height 全部按新图改

    这就是为什么强烈建议所有地图统一 48×48：上面这些都不用碰。
