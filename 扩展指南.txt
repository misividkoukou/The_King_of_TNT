TKOT 扩展指南 —— 新增一种 TNT 道具
==================================================

以新增一种叫 <name> 的变体为例（例如 shock / cluster / heavy）。
只要 4 个文件 + 1 行发放，其余机制全部自动复用。


一、必须遵守的 4 条约定
--------------------------------------------------
1. 物品的 custom_data 里必须有 tnt:true 和 type:"<name>"
   → items/clear_tnt、states/overall/clean 靠 tnt:true 统一清理
   → 进度靠 type 区分变体，不能省略

2. 物品组件里必须保留 consumable
   → 玩家"吃"棍子时才触发 consume_item 进度
   → 消耗就是 consumable 自动扣 1，不要再写 clear

3. summon 出来的 TNT 必须带 thrown_tnt 标签
   → states/reset 的 kill @e[tag=thrown_tnt] 靠它清理残留
   → owner 写入也靠它定位

4. 瞄准计算一律走 item:common/aim
   → 不要复制那 36 行，改速度只改它一处


二、新建的文件（4 个）
--------------------------------------------------

【1】进度：data/item/advancement/<name>_tnt_stick.json
--------------------------------------------------
{
  "criteria": {
    "consume": {
      "trigger": "minecraft:consume_item",
      "conditions": {
        "item": {
          "items": "minecraft:stick",
          "predicates": {
            "minecraft:custom_data": "{tnt:true,type:\"<name>\"}"
          }
        }
      }
    }
  },
  "rewards": {
    "function": "item:<name>_tnt/throw_tnt"
  }
}

注意：predicates 里的字符串必须和物品 custom_data 完全对应。


【2】投掷入口：data/item/function/<name>_tnt/throw_tnt.mcfunction
--------------------------------------------------
# 撤销进度，否则 consume_item 只会触发一次
advancement revoke @s only item:<name>_tnt_stick

# 公共瞄准：探针 → 方向 → storage tkot:throw → 删探针
function item:common/aim

# 召唤
execute at @s run function item:<name>_tnt/throw_tnt_with_macro with storage tkot:throw


【3】召唤宏：data/item/function/<name>_tnt/throw_tnt_with_macro.mcfunction
--------------------------------------------------
$summon minecraft:tnt ~ ~1.62 ~ {Tags:["thrown_tnt"],fuse:60,Motion:[$(mx)d,$(my)d,$(mz)d]}
data modify entity @e[type=minecraft:tnt,tag=thrown_tnt,limit=1,sort=nearest] owner set from entity @s UUID

fuse 单位是 tick：20 = 1 秒，60 = 3 秒（默认保险引信）。
如果这个变体还需要"每 tick 做点什么"（例如落地即炸），就在 Tags 里再加一个自己的标签，
见下面第四节。


【4】发放：改现有文件即可，不用新建
--------------------------------------------------
· 持续补给（每 3 秒）  → data/tkot/function/states/2/give_item.mcfunction 里加一条 give
· 每局只发 1 个        → data/tkot/function/states/2/spread.mcfunction 里加一条 give（瞬爆弹就是这么发的）
· 调试手动发           → data/item/function/temp.mcfunction 里加一条 give @s

give 模板（整行复制，改三处：type、显示名、数量）：

give @a[team=!debug,gamemode=!spectator,scores={statu=2}] minecraft:stick[minecraft:max_stack_size=99,minecraft:use_cooldown={seconds:0.5,cooldown_group:"tnt_throw"},minecraft:custom_data={tnt:true,type:"<name>"},minecraft:consumable={consume_seconds:0,animation:"none",sound:"intentionally_empty",has_consume_particles:false},minecraft:item_model="minecraft:tnt",minecraft:item_name={"text":"<显示名>"}] 1


三、不用改的东西（已自动覆盖）
--------------------------------------------------
· items/clear_tnt       —— 用 custom_data~{tnt:true}，新变体自动被清
· states/overall/clean  —— 每秒清所有无 tkot_keep 的地面物品
· states/reset          —— kill @e[tag=thrown_tnt]，只要第 3 条约定满足
· lobby 相关的一切      —— 与弹药无关


四、需要"每 tick 行为"的变体（可选）
--------------------------------------------------
以瞬爆弹为例，它需要"贴地就引爆"：

1) 召唤时多打一个标签
   $summon minecraft:tnt ~ ~1.62 ~ {Tags:["thrown_tnt","instant_explode_tnt"],fuse:60,...}

2) 新建 data/item/function/<name>_tnt/tick.mcfunction
   execute as @e[type=minecraft:tnt,tag=<你自己的标签>] at @s unless block ~ ~-0.1 ~ #minecraft:air run data modify entity @s fuse set value 1

3) 在 data/item/function/tick/tick1.mcfunction 里加一行
   function item:<name>_tnt/tick

tick1 是全局每 tick 循环，已经在跑了（item:load 里调度），直接加调用即可。


五、想做"不同变体不同初速度"（进阶）
--------------------------------------------------
目前 item:common/aim 把速度系数写死成 0.000015（= 1.5 格/刻），它已经是宏函数（带 $(lat)）。
若要每个变体不同速度，再加一个 $(spd) 参数：

  $execute store result storage tkot:throw mx double $(spd) run scoreboard players get @e[tag=tmp_dir,limit=1] calc_x
  （my / mz 同理）

然后在 throw_tnt 里先写 storage：

  data modify storage tkot:throw spd set value 0.000015    # 或别的系数
  function item:common/aim with storage tkot:throw

注意：一旦加了 $(spd)，所有调用方（normal / instant / multishot）都必须保证
tkot:throw.spd 已存在，否则会报宏参数缺失。


六、改完必做
--------------------------------------------------
1. /reload
2. 退出并重新进入存档（进度文件改动必须重新扫描，否则新的 criteria 不生效）
3. 检查聊天栏有没有 <unknown function> / 宏参数缺失
4. 拿新道具试扔一次，再看 states/reset 后场上是否干净


七、常见坑
--------------------------------------------------
· 进度 criteria 里的 type 和物品 give 里的 type 不一致 → 扔不出来
· 忘了 advancement revoke → 只能扔第一次
· TNT 没打 thrown_tnt → 回合结束清不掉，会在结算/大厅爆炸
· 忘了 consumable → 棍子吃不掉，进度不触发
· 复制了 common/aim 的内容而不是调用 → 以后改速度要改多处
· 改完进度文件没退出重进存档 → 看起来"什么都没生效"


八、扇形多重射击 —— 完整实例
--------------------------------------------------
现成例子：item:multishot_tnt（一次 3 颗、呈扇形散开、fuse 与初速和普通弹一致）。

核心思路：不用三角函数，用「探针侧移」做出方向偏转。

  探针原本放在「眼睛前方 10 格」，连线方向 = 正前方。
  把探针改成「前方 10 格 + 侧向 lat 格」，连线就带上了横向分量：
      Motion = 0.15 × (10·前方 + lat·左方)
      → 前进 1.5 格/刻，同时横移 0.15×lat 格/刻
  lat = 1.5 时横移约 0.225 格/刻 ≈ 4.5 格/秒，三颗 1 秒后散开约 9 格。

为什么用 ^ 局部坐标：它跟着视线旋转，所以仰视/俯视都正确。
如果改用「水平垂直向量」那套算法，垂直看时水平分量趋近 0，扇形会失效。

【1】公共瞄准 item:common/aim —— 已经参数化
    $execute anchored eyes run summon minecraft:marker ^$(lat) ^ ^10 {Tags:["tmp_dir"]}
    其余计算不变，结果仍写进 tkot:throw 的 mx/my/mz。
    调用方必须先写 data modify storage tkot:throw lat set value <数值>，
    否则会报宏参数缺失（普通弹/瞬爆弹现在都显式写 lat = 0）。

【2】投掷入口 data/item/function/multishot_tnt/throw_tnt.mcfunction
    advancement revoke @s only item:multishot_tnt_stick

    data modify storage tkot:throw lat set value 1.5
    function item:common/aim with storage tkot:throw
    execute at @s run function item:multishot_tnt/throw_tnt_with_macro with storage tkot:throw

    data modify storage tkot:throw lat set value 0
    function item:common/aim with storage tkot:throw
    execute at @s run function item:multishot_tnt/throw_tnt_with_macro with storage tkot:throw

    data modify storage tkot:throw lat set value -1.5
    function item:common/aim with storage tkot:throw
    execute at @s run function item:multishot_tnt/throw_tnt_with_macro with storage tkot:throw

    data modify entity @e[type=minecraft:tnt,tag=multishot_tnt,sort=nearest,limit=1] owner set from entity @s UUID

    ★ 这一行不要照抄成 limit=3：data modify entity 只接受【单个】实体。
      实际代码里 owner 是在 throw_tnt_with_macro 中「每召唤一颗、紧跟一行 limit=1」写入的，
      见 data/item/function/multishot_tnt/throw_tnt_with_macro.mcfunction 第 5-7 行的注释。

【3】召唤宏 data/item/function/multishot_tnt/throw_tnt_with_macro.mcfunction
    只召唤 1 颗，由上面循环调用 3 次：
    $summon minecraft:tnt ~ ~1.62 ~ {Tags:["thrown_tnt","multishot_tnt"],fuse:60,Motion:[$(mx)d,$(my)d,$(mz)d]}

【4】调参
    · 散得更开：把三个 1.5 改成 2.5 / 3
    · 5 颗：补成 3 / 1.5 / 0 / -1.5 / -3 的对称组合
    · 竖直扇形：把 aim 里的 ^$(lat) 改成 ^ ^$(lat) ^10（lat 变成上下偏移）
    · 想要「平行排开」而不是扇形：那是另一种做法 —— 三颗方向相同、召唤位置错开，
      summon 里把 ~ ~1.62 ~ 换成 ^-0.6 ^ ^1 之类，但那样不散开

【5】清理不用改
    三颗都带 thrown_tnt，states/reset 的 kill @e[tag=thrown_tnt] 会一起清掉。
    额外打的 multishot_tnt 标签只是给 owner 定位用的，不参与清理。


九、新增一张地图
--------------------------------------------------
前提：新地图也是 48×48×48，落点和现有地图完全相同
（原点 (0,0,-48)，区域 x 0..47 / z -48..-1，中心 (24,-24)）。
这样场上所有坐标都不用改，只有模板名不同。

【1】保存结构模板
    · 用结构方块框住整张图，单边不能超过 48
    · 保存的名字随意（例如 map_2_1），导出成 .nbt
    · 放到 tkot/data/tkot/structure/<模板名>.nbt
    · 模板 id 就是 tkot:<模板名>，例如 tkot:map_2_1

【2】新建 tkot/data/tkot/function/maps/mapN.mcfunction
    直接复制 map1.mcfunction 改三处：

    data modify storage tkot:map id     set value <N>            ← 地图编号
    data modify storage tkot:map name   set value "<显示名>"      ← map_intro 会显示
    data modify storage tkot:map struct set value "tkot:<模板名>" ← 模板 id

    ★ 后面的 x1/y1/z1/x2/z2/x/z/y_debug/max_height 全部照抄，不要动。

    ★ 出生点不写在这里：每张图有自己的 9 个落点文件，见下面【2.5】。

    ★ 时间与刷怪规则必须在这张图里显式写，例如：

      time set day
      gamerule spawn_monsters false

      原因：map1 会设成 night + 刷怪，这些都是【全局状态、不会自动复原】。
      不写的话，新地图会继承上一张图的昼夜和刷怪规则。


【2.5】新建出生点表 states/2/tp/spawns/mapN.mcfunction
--------------------------------------------------
    复制 spawns/map1.mcfunction，只改 9 行坐标（朝向可省）：

      tp @a[team=!debug,gamemode=!spectator,scores={spawn_point=1}] 12 1 -12
      tp @a[team=!debug,gamemode=!spectator,scores={spawn_point=2}] 12 1 -24
      ...
      tp @a[team=!debug,gamemode=!spectator,scores={spawn_point=9}] 36 1 -36

    · spawn_point 是 1..9 的分数：单人混战每人随机一个点；
      组队模式红/黄/蓝/绿固定用 1/2/3/4 号点（同队共用一个落点）。
    · 坐标必须在这张图里、且脚下有实体方块，否则人会被直接 tp 到空中掉下去。
    · 还要在 states/2/tp/spread_players.mcfunction 末尾补一行 dispatch：
        execute if score #map_num int matches <N> run function tkot:states/2/tp/spawns/mapN
      漏了这行 → 抽到这张图时没人被传送，全员留在上一个落点。

【3】改 tkot/data/tkot/function/maps/pick.mcfunction
    三件事：

    ① 总数
       data modify storage tkot:map total set value <地图总数>
       （map_intro 的 $(total) 依赖它，漏了会报宏参数缺失）

    ② 抽图行
       地图只有 1 张时（random 范围必须 ≥2，所以不能写 1..1）：
         scoreboard players set #map_num int 1
       地图 ≥2 张时：
         execute store result score #map_num int run random value 1..<总数>

    ③ dispatch —— 每张图一行，且必须覆盖 1..<总数> 全部区间
       execute if score #map_num int matches <N> run function tkot:maps/mapN

       ★ 漏一行会怎样：抽到没 dispatch 的号 → tkot:map 里留着上一局的旧数据
         → 模板名和坐标全错 → 铺图失败、场地是空的。

【4】不用改的东西（因为共用场地）
    · forceload add / remove 的坐标 —— 所有 48×48 图都是 0 -48 47 -1
    · maps/map1_spectate 的包围盒与观察点 —— 所有图共用一份
    · states/3/map_returen/* 的清理范围 —— 参数从 storage 读，自动跟随
    · states/3/place、place_quiet —— 模板名从 storage 读，自动跟随
    · states/2/tp/spread_players —— 只按图号 dispatch 到 spawns/mapN，落点表自己维护

【5】测试
    · /reload（新加了 structure 文件，必须重新加载数据包才能被扫描到）
    · 想指定测某张图：把 pick 里改成 scoreboard players set #map_num int <N>
    · 检查聊天栏有没有「开战前铺图失败：tkot:xxx」—— 有的话就是模板名或文件路径不对
    · 开一局，看完 states/3 复位后场地上是否干净（说明 max_height 和清理范围对得上）

【6】如果新地图【不是】48×48，或落点不同
    那么共用场地的前提就不成立了，需要额外做：
    · maps/pick 的 forceload 改成按图号区分
    · 新增 maps/mapN_spectate（包围盒 = 新图尺寸）
    · states/overall/in_game 里的边界判定改成按图号 dispatch
    · states/3/finish 与 states/abort 的 forceload remove 改成按图号区分
    · mapN 里的 x1/y1/z1/x2/z2/x/z/max_height 全部按新图改

    这就是为什么强烈建议所有地图统一 48×48：上面这些都不用碰。

【7】想让落点自动找安全位置（可选）
    现在每张图都已经有自己的 9 个硬编码点（spawns/mapN.mcfunction），
    足够避开墙和坑，通常不需要动这里。

    如果某张图实在懒得一个个摆点，可以整张图改用原版分散：

      $spreadplayers $(x) $(z) 4 8 true @a[team=!debug,gamemode=!spectator,scores={statu=2}]

    放进 spread_players.mcfunction，替掉按图 dispatch 的那几行即可
    （$(x) $(z) 来自 tkot:map，是场地中心）。

    代价：落点不可控，可能把两个人分到掩体两侧，也可能分进坑里，
    观感和公平性都不如手摆，只建议当临时方案用。






十、新增一个职业（只改 4 处）
--------------------------------------------------
代码里没有"职业总表"，新增职业就按下面 4 步走，别的地方不用碰：

【1】新建 jobs/give_item/jobN.mcfunction
     data/tkot/function/jobs/give_item/jobN.mcfunction
     照着 job1..3 写 give @s ...（上下文是玩家，用 @s）。

【2】jobs/judge.mcfunction
     加一行：
       execute if score @s job matches N run function tkot:jobs/give_item/jobN

【3】jobs/read.mcfunction
     加两行（赋值 + 提示）：
       execute if score @s job_trigger matches <N+1> run scoreboard players set @s job N
       execute if score @s job_trigger matches <N+1> run tellraw @s [...]
     ★ trigger 分值 = job 分值 + 1，因为 trigger 1 被"重开面板"占用。

【4】jobs/bar.mcfunction
     面板加一个按钮，click_event 的 command 写 trigger job_trigger set <N+1>。
     jobs/bar_self 只是转发 bar，不用改。

不用改的东西：
  · ticks/sec1 的 job_trigger 判断已经放宽成 1..（具体分值由 jobs/read 精确分发）
  · states/reset 每局结束会 scoreboard players reset @a job，职业不会带进下一局
  · 想让人在图鉴里看到新职业，手动补 data/tkot/dialog/guide_jobs.json（静态文本）


十一、需要"每 tick 行为"的第二种坑：弹跳 TNT
--------------------------------------------------
文件（4 个，命名沿用普通弹）：
  data/item/advancement/bounce_tnt_stick.json
  data/item/function/bounce_tnt/throw_tnt.mcfunction
  data/item/function/bounce_tnt/throw_tnt_with_macro.mcfunction
  data/item/function/bounce_tnt/tick.mcfunction

它与瞬爆弹的区别：瞬爆只要"贴地就引爆"，一条判断就够；弹跳要"每次触地弹一次、连弹 3 次"，
所以用「装填 / 触发」两态，而不是看速度符号：

  # 1. 脚下是空气（在空中）→ 装填
  execute as @e[type=minecraft:tnt,tag=bounce_tnt] at @s if block ~ ~-0.1 ~ #minecraft:air run scoreboard players set @s bounce_arm 1
  # 2. 贴地 + 已装填 → 记一次弹跳
  ... unless block ~ ~-0.1 ~ #minecraft:air if score @s bounce_arm matches 1 run scoreboard players add @s bounce 1
  # 3. 第 1~3 次触地 → 上弹，然后清掉装填（同一段贴地不会再触发）
  ... if score @s bounce matches 1..3 run data modify entity @s Motion[1] set value 0.6d
  ... if score @s bounce_arm matches 1 run scoreboard players set @s bounce_arm 0
  # 4. 第 4 次触地 → 摘标签，退化成普通 TNT
  ... if score @s bounce matches 4.. run tag @s remove bounce_tnt

★ 为什么不用「Motion[1] 为负」判断在下落（v1 的写法，实测失败）：
  每 tick 的函数在【实体物理之后】执行，TNT 撞地那一 tick 竖直速度通常已经被碰撞清零，
  于是绝大多数落地读不到负值 → 直接不弹，表现和普通 TNT 一模一样。
  用装填标记就与速度符号无关：每次触地必然触发一次，弹起后在空气中自动重新装填。
★ 坑一：只判断"贴地"会每 tick 都成立，落地瞬间就把次数上限打满（"一落地连弹三次"）。
  必须靠"装填"消抖：贴地不动时永远不会再装填。
★ 坑二：fuse 要给够。上弹 0.6 格/刻（约 3 格高）时一次完整弹跳约 26 tick，3 次要 78 tick 出头，
  所以弹跳弹用的是 fuse:100（5 秒），普通弹仍是 60。fuse 太短会"只弹两下就炸"。
  （0.45 实测偏矮，0.6 是抬高一档后的值；想更高就再改这一个数，同时把 fuse 往上加。）
★ 上限 3 次后摘掉 bounce_tnt 标签；它仍然带 thrown_tnt，所以 states/reset 的清理不用改。
★ 冷却用独立组 bounce_throw，不和抛射型/瞬爆型共用 tnt_throw（否则会互相卡冷却）。
★ Motion 仍可能被物理覆盖（这一版没再验证到该情况）；若实机仍几乎不弹，
  备选方案是「贴地时 kill 掉旧 TNT，再 summon 一颗带新 Motion 的 TNT」，保留 thrown_tnt 与 owner。


十二、模式告示牌（modes/setup 注释里提到的那一节）
--------------------------------------------------
mode_set 是 trigger 计分板：告示牌的 click_event 对非 OP 玩家只能跑 trigger，
所以牌子内容用 /data merge block 写，而不是直接 run_command 改 #gamemode。

三条命令模板在 给人看的.txt 的"牌子"一节（第 8-10 行），复制后只改坐标：

  /data merge block ~ ~ ~ {front_text:{has_glowing_text:true,messages:['{"text":"[ 单人混战 ]","color":"yellow","bold":true,"click_event":{"action":"run_command","command":"trigger mode_set set 1"}}','','','']}}
  ... set 2（系统分组）/ set 3（自选分组）同理

读取链路：states/0/sec1（每秒一次）→ modes/read 按分值分发 → 处理完 reset 并重新 enable。
所以「牌子点了没反应」优先查：是否在 #steps=0 的大厅阶段、mode_set 是否有权限、
modes/read 里有没有对应分值的分支。


十三、图鉴（/dialog）需要手动同步的地方
--------------------------------------------------
玩家在大厅点聊天栏的 [ 查看图鉴 ] 打开（老玩家可自己 /trigger guide_trigger set 1），
入口是 tkot:guide_main。五个文件：

  data/tkot/dialog/guide_main.json    主菜单（dialog_list，列出四个子页）
  data/tkot/dialog/guide_items.json   道具一览
  data/tkot/dialog/guide_jobs.json    职业一览
  data/tkot/dialog/guide_maps.json    地图一览
  data/tkot/dialog/guide_modes.json   模式说明

· dialog 是注册表条目，/reload 后即生效，不像 advancement 必须退出重进存档。
· 正文只支持静态文本（不能用 score / selector / NBT 组件），所以图鉴里写不了"当前分数"。
· 新增道具 → 补 guide_items.json；新增地图 → 补 guide_maps.json；新增职业 → 补 guide_jobs.json。
· 页间跳转全靠按钮里的 {"type":"show_dialog","dialog":"tkot:xxx"}，不需要命令、不需要 trigger。
· 入口门控在 guide/tick1：只在 #steps=0（大厅）放开，开战后自动收回 trigger 权限。
· 子页的 external_title 就是主菜单按钮上显示的文字，改名字改这个字段。


十四、大厅综合菜单（图鉴 + 战绩入口）
--------------------------------------------------
每个玩家【每次回到大厅】都会收到一条 tellraw 菜单：生涯击杀/死亡速览 + 两个按钮。

  文件：data/tkot/function/lobby/menu.mcfunction
  触发：states/0/sec1 的 0.7 段（每秒一次，看到缺标记就发）
  标记：lobby_menu_shown
        · 发完立刻给自己打上（所以一秒只发一次，不会刷屏）
        · ticks/sec1 在 #steps ≠ 0（离开大厅）时统一摘掉 → 下一局回来再弹
  按钮：click_event 只能跑 trigger，所以
        [ 图鉴 ] → trigger guide_trigger set 1   （guide/tick1 处理）
        [ 战绩 ] → trigger lobby_trigger set 1   （statistics/tick1 处理）
        两个 trigger 都只在大厅补权限，战斗中点了无效。

想加第三个入口（例如"练习区"）就照 menu.mcfunction 里现有的按钮再拼一段，
权限交给对应的 tick 函数补 enable 即可。

战绩面板的 K/D 现在是「一位小数的比值」（如 2.3），不再是百分数：
  statistics/kd.mcfunction 负责算：kd = 整数部分、kd_frac = 小数部分（×10 再除，纯整数运算）
  statistics/show.mcfunction 显示，并在 total.death = 0 时不除法、显示 "—（暂无死亡）"


十五、硫方怪 TNT（试验品，管理员专用）
--------------------------------------------------
用来验证"26.2 新增的 minecraft:bounciness 属性到底能弹多高"，
不参与任何发放，只能手动取：

  /function item:sulfur_tnt/give      # 给自己一个"硫方怪TNT（试验）"
  /function item:sulfur_tnt/test      # 不吃道具，直接按视线投一颗（排查用）

文件：
  data/item/advancement/sulfur_tnt_stick.json     吃下 → 触发投掷
  data/item/function/sulfur_tnt/give.mcfunction   管理员取用
  data/item/function/sulfur_tnt/throw.mcfunction  吃道具入口（只负责 revoke 进度）
  data/item/function/sulfur_tnt/test.mcfunction   投射本体：瞄准 + 召唤 + 成功/失败反馈
  data/item/function/sulfur_tnt/summon.mcfunction 召唤（宏）

召唤分两步，故意不写成一整条：
  $summon minecraft:sulfur_cube ~ ~1.62 ~ {Tags:["thrown_tnt","sulfur_test_tnt"],fuse:90,Motion:[$(mx)d,$(my)d,$(mz)d]}
  data modify entity @e[...] equipment.body set value {id:"minecraft:tnt",count:1}
  item replace entity @e[...] armor.body with minecraft:tnt
  $attribute @e[...] minecraft:bounciness base set 1.0

先"裸召唤"再塞方块，是为了让失败可见：实体出不来 = 召唤语句本身有问题；
实体出来了但没 TNT = 两条塞方块的路都不被这个版本接受。

★ Java 版硫方怪【没有独立的 archetype NBT】：原型由 equipment.body 里的方块推导，
  填 minecraft:tnt 就会走 Explosive 原型（有爆炸参数，炸完不分裂小方块）。
★ fuse = -1 是未点燃；给正数就直接点燃。这里给 90（4.5 秒），留时间看弹跳。
★ minecraft:bounciness 取值 0..1、默认 0，1.0 是"落地几乎不衰减速度"。
  Explosive 原型本身还会挂属性修饰符，base 1.0 之后可能被夹到上限，属正常现象。
★ 它带 thrown_tnt，回合结束时 states/reset 的 kill @e[tag=thrown_tnt] 会一起清掉。
★ 这个物品带 custom_data {tnt:true}，所以大厅每秒的 clear_tnt 也会收走，不会留在背包里。

【排查"吃了没反应"】
  1) 先确认已经【退出并重新进入存档】：改 advancement 只 /reload 不会扫描新 criteria。
  2) 再跑 /function item:sulfur_tnt/test：
     能出硫方怪  → 召唤没问题，问题在进度（custom_data 与 advancement 不一致，或没重进存档）
     出不来      → 看聊天栏红字（未知实体 / 语法 / NBT）与 latest.log，按报错改 summon.mcfunction
     出来了没炸  → equipment.body 没塞进去，看 data modify / item replace 哪条报错
